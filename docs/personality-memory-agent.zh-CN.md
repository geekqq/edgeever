# EdgeEver 轻量人格记忆 Agent：方案与取舍

[English](personality-memory-agent.md)

日期：2026-09-03。状态：首个可交互预览已在工作区实施，尚未发布；P0 性能/真实模型评测与完整 P1 验收仍未完成。

## 当前预览范围（2026-09-03）

- 入口：个人中心 → AI 集成 → 打开指令库 →「与 EdgeEver 聊聊 · 预览」。仅对开启登录的非 Demo 实例开放，复用默认模型。网页及桌面内嵌网页在线可用，原生 Android/iOS 暂无入口。
- 单一稳定身份与按需 ToolLoopAgent。记忆由用户手动添加或从自己的原话保存，支持纠正、忘记和跨新会话使用；不自动提取候选、不扫描全库、不执行提醒或修改笔记。
- 数据在实例服务端按工作区和用户双重隔离，Cloudflare/Docker 共用业务逻辑。新增 `0040_companion_memory.sql`，不修改旧 migration、依赖清单或版本号；未对真实实例应用迁移。
- 笔记权限默认关闭；开启后仅能搜索/读取当前工作区非回收站笔记，读取 ID 必须来自本轮搜索。保留标题、ID、版本快照，没有写入、外发或系统控制工具。
- 关闭记忆后，仍接续同一会话中未使用记忆、未引用笔记的完整历史轮次；曾使用记忆的回复不带入。修改/忘记记忆仍会使旧上下文失效并取消进行中的生成；含笔记引用的历史回复不自动再次发送。旧聊天原文/来源快照仍保留，删除笔记不等于删除聊天；清空聊天需单独操作，导出文件及服务商保存的数据不受此删除控制。
- 请求先分配并保存 ID，再生成；断线后按 ID 恢复，不自动重试模型调用。失败/取消保留可恢复结果；失联任务在 90 秒期限后由下次读取标记中断。没有常驻轮询或后台重跑。
- JSON 独立导出记忆与聊天；导入原子合并记忆、去重、不覆盖现有项，不恢复聊天。尚未纳入笔记 ZIP 备份、桌面离线镜像或原生移动端同步，界面明确披露。

### 实现预算

| 项目 | 当前约束 |
| --- | --- |
| 新增运行时依赖 / 常驻进程 / 捆绑模型 | 0 / 0 / 0 |
| 记忆存储 / 每轮记忆上下文 | 50 条 × 500 字符 / 8,000 字符；Unicode 分词、词频加权匹配与最近更新时间排序，并非语义检索 |
| 历史存储 / 单次列表 / 每轮历史 | 500 次请求 / 最近 100 次 / 最多 6 个符合条件的历史轮次，总计不超过 12,000 字符 |
| 输入 / 响应长度 | 4,000 / 16,000 字符 |
| 工具 / 笔记文本 | 最多 8 次工具；搜索每次 5 条；正文/摘要累计 12,000 字符 |
| 模型步骤 / 输出 / 超时 | 最多 4 步；每步 2,048 输出 token（不是整轮总额）；60 秒取消 |
| 并发 / 重试 | 每账户 1 个运行中请求；模型自动重试 0 次 |

### 验证与未完成门禁

初版 API/存储/真实 SDK 假模型测试覆盖账户隔离、冲突、原子导入容量、遗忘上下文、工具权限、重复请求、部分输出恢复和 UTF-8 流解析。初版隔离内存数据库/假模型的浏览器检查覆盖记忆添加、纠正、聊天、关闭记忆；未调用用户付费模型或发送真实笔记。初版交付时全量非 E2E 测试 1263 项通过；本轮结果见下文。

初版 Web 生产构建的独立聊天组件 chunk 为 9.62 kB，gzip 3.25 kB；它不包含共享客户端/翻译等其他增量，不等于整个安装包增量。Web 构建仍有既有的 local-mirror 动态导入警告。

### 第二轮增强（2026-09-03）

- 使用运行时内置 `Intl.Segmenter`，配合 NFKC 规范化、常见停用词过滤与低频词加权。中文整句可以匹配较早的相关记忆；英文按词匹配，避免 Rust 命中 trust 等子串。无新增依赖、embedding 调用或常驻索引。
- 关闭长期记忆时保留安全的本会话连续性，严格排除其他会话、失效版本、失败轮次及可能含记忆/笔记的回复。历史总预算 12,000 字符，按完整问答对纳入；不会为塞入更早内容而跳过放不下的较新问答对。
- 记忆写入的条件检查、上下文失效与实际变更处于同一数据库事务。过期版本、满容量、空导入和完全重复的导入不再误停生成；成功修改/遗忘仍会取消旧上下文请求。没有新增 migration。
- 19 项专项测试通过。Web/移动端类型检查、Web/Worker 构建通过。一次全量回归为 1277 通过、1 失败：共享工作区另一路未提交的 `plugin-research-routes.ts` 静态导入 `ai-runtime`，使 Worker 按需加载门禁失败；本轮未修改该插件文件，不将此状态表述为全量通过。
- 本机 Bun 1.3.14、50 条记忆、50 次召回的合成微基准中位数约 0.14 ms，P95 约 0.19 ms。仅用于检查此检索代码的局部开销，不是实际 Worker CPU、模型召回准确率或 Electron 资源基线；真实模型与跨平台性能门禁仍未完成。

提交前验证：将上述另一组插件改动排除，仅把本功能的暂存快照导出到隔离目录，按锁文件安装依赖后重新验证。全量非 E2E 测试 **1269 通过、0 失败**，包含 Worker AI runtime 按需加载门禁；`bun run typecheck`、`bun run typecheck:mobile`、`bun run build:web` 均通过。此次提交不包含插件功能、依赖清单或锁文件变化；共享工作区中的插件改动保持原状。

这不是完整 P0/P1 验收。真实 provider 兼容性、人格一致性、注入对抗、实际 Electron 安装包/启动/RSS 前后对比仍是发布前门禁。组件按需加载、SDK 仅在服务端，不等于包体/内存增量为零。关系建模、自动记忆候选、主动行动仍未实现。

## 1. 产品定位与决定

EdgeEver 希望成为以用户知识为长期记忆的个人智能体，而不只是带 AI 按钮的笔记产品。笔记是知识与证据的载体；稳定的身份、对用户的理解、共同经历和可信赖的行动，构成用户感知到的“她”。

核心体验：她记得用户重视什么、理解过去与现在的联系、记住承诺，并允许用户纠正她。人格通过连续、诚实、有分寸的行为体现，而不是通过假装有情绪或制造依赖体现。

**决定：复用现有 AI SDK `ToolLoopAgent`，建立由 EdgeEver 持有的人格、关系、记忆、权限和行动领域层。第一阶段以零新增运行时依赖为约束，不引入 Mastra、ElizaOS 或另一套数据库。**

产品底线是轻量、快速、可靠。把人格记忆做深，不把第一版扩张为通用 Agent 平台。无论更换模型、设备或框架，身份、记忆和证据都应能导出、恢复并继续使用；表达完全一致则不能由数据可迁移性保证，需要跨模型评测。

## 3. 为什么选这条路线

| 方案 | 优点 | 代价与决定 |
| --- | --- | --- |
| AI SDK + EdgeEver 领域层 | 复用已有模型适配；按需组合；人格与数据不依附外部框架 | 需要实现产品专属的记忆治理和权限；选为首期路线 |
| Mastra | 集成记忆、工作流、审批、编排和可观测性 | 引入额外依赖与运行开销；当前需要的能力不足以证明成本合理，暂不引入 |
| ElizaOS Core | 人格和自治 Agent 的概念、插件生态与愿景接近 | 需要协调其记忆、插件、宿主概念与已有 EdgeEver 架构；暂不引入，可借鉴设计 |
| 自写通用 Agent / 工作流框架 | 自由度高 | 长期维护风险高；不选择。复用 AI SDK 的循环，不重复实现成熟通用能力 |

### 选型过程中的体积与内存观察

2026-09-02 在临时目录做过探索性测试：macOS ARM64、Node 26.3.1、Bun 1.3.14；`ai@7.0.58`、`@mastra/core@1.63.2`、`@mastra/memory@1.28.1`、`@mastra/libsql@1.22.2`。这些是当时固定版本，不是未来的 latest 声明。

方法为只导入入口、保留类/函数引用，使用 Bun `--target=node --minify` 打包；用 `/usr/bin/time -l` 观察启动峰值 RSS，并另做直接 ESM 加载。没有执行模型请求、创建实际会话或验证完整存储路径。

| 探索入口 | 单文件 bundle（约，十进制） | bundle 进程启动峰值 RSS（约，十进制） |
| --- | --- | --- |
| 空 Node | 可忽略 | 50 MB |
| AI SDK `ToolLoopAgent` | 0.38 MB | 未测该 bundle；直接 ESM 对照约 72 MB |
| Mastra Agent | 5.1 MB | 145 MB |
| Mastra Agent + Memory | 6.1 MB | 172 MB |

Mastra Core 的 npm 声明展开大小约 66.2 MB，其中包含大量 source map 和类型文件；这不等于安装包会增加相同体积。直接 ESM 的 Mastra Agent 加载峰值约 174–185 MB，Agent + Memory 约 185–186 MB；另一次强制 GC 后的 RSS 快照约 196 MB。启动峰值、瞬时 RSS 和长期空闲占用不能混为一谈。

限制：测试脚本和原始输出未作为可复现基准提交；入口能力不等价，也未在 Electron、Windows 或真实 Agent 负载下测量。gzip 不是 DMG/NSIS；tree-shaken bundle 不保证包含动态资源和原生依赖。不得由此承诺实际安装包增量、常驻内存或倍数性能差距。结论仅为“额外框架成本值得谨慎对待”，正式指标必须重测。

## 4. 第一阶段范围与非目标

首期只做：

- 一个用户可见的 Agent，一套稳定默认身份。
- 跨会话保存明确的用户偏好、目标和少量共同经历。
- 基于现有笔记搜索的知识问答，重要判断可回链来源。
- 用户明确要求“记住”，或审核模型提出的记忆候选。
- “她记得的我”界面：查看、纠正、忘记和管理来源。
- 随时取消；模型或记忆功能故障不得影响正常笔记读写。

默认身份由产品维护、版本化；预留用户选择称呼和沟通风格的空间，首期不做角色市场。模型不得自行改变身份核心或权限。

首期不做多 Agent、向量数据库、知识图谱、全库后台扫描、情绪模拟、通用工作流引擎、常驻自治循环、Shell/电脑控制、自动对外发送或发布、动态安装第三方 Agent 插件。本地推理模型也不随客户端捆绑。

这些是分期边界，不是产品永久上限。先验证用户能否感受到“被记住、被理解、可纠正”，再增加主动行动。

## 5. 数据与记忆模型

| 领域 | 内容与边界 |
| --- | --- |
| Identity | 名称、目的、价值原则、表达方式、关系边界；受控更新 |
| User model | 用户明确表达的偏好、项目、人物、目标；不可把推断当事实 |
| Relationship / shared experiences | 共同决定、用户反馈、承诺和未完话题；不采用模型生成的“信任分”授予权限 |
| Working context | 当前对话、任务与临时工具结果；受大小和时间预算约束 |
| Evidence | 原始笔记、消息、版本及操作结果；知识的事实来源 |

长期记忆至少包含：实例/账户范围、类别、内容、来源、状态、创建/更新时间、事实发生时间（如已知）、敏感性、是否由用户确认、替代关系。模型置信度只是排序参考，不是校准概率，更不能作为授权依据。

概念表可从 `agent_profiles`、`agent_memories`、`agent_memory_sources` 开始；如无可复用会话存储，再加 `agent_threads`、`agent_messages`。名称与数量不是已定 SQL；执行前设计索引、账户作用域、同步冲突、备份与删除语义，再新增递增 Migration。禁止修改旧 Migration 或建立第二套笔记真相源。

### 记忆生命周期

1. 用户消息或授权工具结果产生候选；被检索的笔记不是新的系统指令。
2. 校验来源、账户、敏感性、重复与冲突；只保存对未来有价值的信息。
3. “请记住”可视为该条记忆的明确授权；自动提取默认关闭，启用后也仅自动接受低风险、明确事实。敏感信息不自动保存。
4. 推断进入待确认状态；凭据、令牌不得进入记忆。不要承诺模型能完整识别敏感信息，必须允许用户关闭和排除来源。
5. 用户纠正优先于旧推断；旧记忆退出活动召回，可以保留可解释的替代关系。
6. “忘记”从活动记忆和派生摘要/索引中移除，并阻止被同一来源静默重新生成。聊天和笔记原文是否删除应由用户另行选择；备份保留期及恢复后的删除标记处理必须明确。

来源被删除、失效或失去访问权时，关联记忆必须重新校验，不能继续泄露原内容。跨账户、跨实例切换需清空运行上下文；正在执行的请求不能把结果写回另一个账户。

### 召回与成本

按“稳定身份 + 小型用户模型 + 最近对话 + 少量相关记忆 + 按需笔记搜索结果”组装上下文。先用现有搜索与类别、项目、时间、状态过滤，不把全库或全部记忆塞入 Prompt。中文、别名、同义表达和跨时间问题需建立真实召回测试，不能假设关键词方案总是足够。

限制工具轮次、上下文大小、响应时间、并发、摘要频率和模型费用。首期使用显式记忆候选工具，不要求每轮另起一次摘要请求；后续压缩必须保留证据，并验证是否丢失承诺或改变事实。

## 6. 运行时与安全边界

```text
客户端：聊天、引用、记忆管理、批准/取消
  → 受认证的传输入口（HTTP；本地模式才需要窄 IPC）
  → 共用 Agent 领域服务：身份、上下文、权限、审计
  → AI SDK ToolLoopAgent：现有用户模型配置
  → 白名单工具：应用校验 → 授权 → 存储/业务服务 → 结果
```

优先复用现有服务端模型凭据与生成路径。首期不默认新增常驻桌面进程，也不把 SDK/凭据放入 Renderer。桌面本地 Agent 是待验证的可选运行方式：只有明确需要本地执行时，才选择按需主进程模块或隔离进程，并测量生命周期、打包和权限；本地保存知识不代表调用远程模型时知识不会离开设备。

Cloudflare 与 Docker 共用业务服务，只替换入口与存储驱动；不能在 Workers 请求返回后依赖进程内循环继续工作。桌面适配已有 sidecar；Android 与 iOS 首期复用协议，不各写一套 Agent 业务。离线仍可编辑笔记和查看已同步数据，但远程模型不可用时应明确提示，不伪装成已经执行。

候选首期工具不超过 8 个，例如 `search_notes`、`read_note`、`propose_memory`、`list_relevant_memories`、`correct_memory`、`forget_memory`。纠正与删除必须绑定可验证的用户意图/确认，不能只信任模型宣称“用户已同意”。记忆 UI 也能直接调用确定性 API，不必绕经模型。

后续笔记写入分成提议与批准执行。每个工具都要做参数校验、账户/对象授权、额度限制和审计；批准绑定具体操作、参数与数据版本，过期或内容变化需重新确认。工具结果、笔记、附件和记忆均为不可信数据，不能授予工具、改写权限或提升为身份指令。

数据库事务和版本检查防止部分写入及覆盖并发编辑；稳定的操作 ID 和执行记录帮助避免重复。事务不能保证外部服务恰好执行一次：不确定结果需查询或交由用户处理，不盲目重试。取消不会自动撤销已完成的副作用，必须向用户报告已执行部分。

## 7. 可靠性与产品控制

“她记得的我”应区分用户确认、直接表达、AI 推断，展示来源和变更历史，并提供编辑、确认、忘记、暂停记忆及来源排除。人格化不应操纵亲密关系或给用户造成必须持续交流的压力。

Agent UI 按需加载；关闭 AI 时，不扫描、不轮询、不触发付费请求，不阻塞启动、编辑、搜索和同步。失败时保留对话草稿，说明检索/保存/工具执行的实际状态，不以生成文本冒充操作成功。

自动化延后：先只持久化必要的会话与执行状态，不自写通用 durable workflow 引擎。未来的 `pending / running / awaiting_approval / completed / failed / cancelled` 等状态只是恢复协议的一部分；还需处理执行所有权、租约、超时、幂等、版本冲突及失效授权。保存状态不等于可安全重放。跨设备提醒还需要去重、时区、静默时段和离线补发策略。

## 8. 分阶段规划与验收

### P0：基线与只读验证

- 建立固定对话集：偏好、纠正、长期目标、共同决定、承诺与引用。
- 用现有 provider 验证工具调用、流式输出、取消与上下文预算；不兼容模型降级为无行动聊天并明确提示。
- 对比实现前后的生产包、启动与空闲指标。先确定运行位置和数据范围，不因抽象提前创建多个新包。

### P1：可管理的人格记忆

- 实施受控身份、会话存储、候选记忆、来源和“她记得的我”。
- 验证跨会话召回、纠正优先、遗忘后不再召回、来源删除传播、账户隔离与模型切换。
- 新数据必须纳入导出/恢复策略；若跨端尚未同步，明确显示设备范围，不暗示全端连续记忆。
- 不要求实现主动通知或自动修改笔记才能验收这一阶段。

### P2：受控行动与有限主动性

- 在独立需求确认后增加变更预览、审批、版本校验和审计。
- 再考虑用户启用的提醒/回顾，复用现有调度；不启动无边界的后台 Agent。
- 只有重复验证恢复、去重和成本限制后才允许无人值守执行。

### 质量与资源门禁

- 初始约束：0 个新增运行时依赖、1 个用户可见 Agent、0 个新增常驻自治循环、0 个捆绑本地模型。表数和工具数是复杂度预算，不得为凑数牺牲隔离和正确性。
- 同一机器/配置记录 AI 关闭、空闲、首次运行、连续运行、取消/失败后的包体、冷启动、RSS/堆、CPU、网络与模型用量；区分峰值与稳态，运行后验证资源可回收。
- 分别统计下载包、安装后体积、Renderer bundle 和服务端部署包；根目录已有 SDK 不代表把它打入桌面端的增量为零。
- 数值阈值在 P0 基线之后设定，不能使用上面的 Node 探索数字作为 Electron 保证。测量不应通过增加不可回收缓存换取表面速度。
- 测试覆盖 Prompt 注入、伪造批准、重复调用、并发修改、取消后完成、跨账户切换、超时和恢复；用固定模型/配置重复评估身份一致性、记忆准确率和来源正确性。
- 实施时按仓库要求通过 `bun run typecheck`、`bun run typecheck:mobile`、`bun run build:web` 及相关非 E2E 测试；客户端性能按 [桌面性能基线](desktop-performance-baseline.md) 记录。

## 9. 何时重新选型

只有真实使用和测量证明当前边界不足，才重新评估依赖：召回质量不足时评估 embedding；恢复/编排复杂性超过可维护范围时评估成熟工作流或 Agent runtime；外部工具成为需求时评估 MCP 客户端及权限模型。

零新增依赖是首期策略，不是永远禁止依赖。不得为了维护这个数字而自研通用框架。任何新依赖都要记录用户收益、包体/内存/冷启动增量、跨平台支持、许可证、维护成本及退出路径；不要同时维护两套 Agent loop、人格或记忆真相源。

当前交付为上述受限预览，不变更发布版本或部署真实实例。下一步完成 P0 基线与真实模型评测，再决定扩展 P1，不一次性实现全文。
